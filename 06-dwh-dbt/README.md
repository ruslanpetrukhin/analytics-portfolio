# Data Warehouse & dbt Architecture

## О проекте

Проектирование архитектуры аналитического хранилища данных (DWH) для учебной e-commerce базы PostgreSQL.

Цель проекта — показать, как можно организовать переход от операционной базы данных к аналитической модели, подготовленной для построения отчётности и бизнес-анализа.

В проекте рассматриваются архитектура DWH, моделирование данных по принципу Star Schema, историчность измерений SCD Type 2 и трансформации данных с использованием dbt.

**Важно:** исходная база PostgreSQL реализована и используется в других проектах портфолио. Архитектура DWH и dbt-модели в этом проекте спроектированы, но не развёрнуты и не реализованы в рабочей среде.

## Архитектура

Предлагаемая последовательность обработки данных:

1. **Source** — операционная база PostgreSQL.
2. **Raw** — загрузка исходных данных без изменения бизнес-смысла.
3. **Staging** — очистка, приведение типов и стандартизация.
4. **Intermediate** — объединение и подготовка данных для аналитических моделей.
5. **Marts** — факты и измерения для аналитики.
6. **BI** — использование подготовленных данных в Power BI и SQL-отчётах.

[Посмотреть диаграмму архитектуры DWH](diagrams/dwh_architecture.md)

## Модель данных

В качестве целевой модели выбрана Star Schema с двумя фактами:

- `fct_order_items` — продажи на уровне товарной позиции заказа.
- `fct_order_status_history` — история изменения статусов заказов.

Измерения:

- `dim_customers` — клиенты с поддержкой SCD Type 2.
- `dim_products` — товары.
- `dim_date` — календарь.
- `dim_order_status` — справочник статусов заказов.

[Посмотреть схему Star Schema](diagrams/star_schema.md)

## dbt: подход к трансформации

В проекте предусмотрено использование dbt для управления SQL-трансформациями внутри DWH.

Основные принципы:

- разделение моделей на staging, intermediate и marts;
- повторное использование бизнес-логики через macros;
- контроль качества данных через tests;
- отслеживание изменений атрибутов клиентов через snapshots;
- использование incremental models для обновления больших таблиц.

Отдельное внимание уделено централизованному определению статусов заказов, учитываемых при расчёте выручки.
