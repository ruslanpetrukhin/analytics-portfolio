# Исходная база данных — PostgreSQL

## 1. Общее описание

В качестве исходной системы используется учебная база данных интернет-магазина `FOR CV`, разработанная на PostgreSQL.

База содержит информацию о клиентах, товарах, заказах, товарных позициях и истории изменения статусов заказов.

Она выступает источником данных для проектируемого аналитического хранилища данных (Data Warehouse, DWH).

## 2. Структура базы данных

| Таблица | Назначение | Первичный ключ |
|---|---|---|
| `customers` | Информация о клиентах | `customer_id` |
| `products` | Каталог товаров | `product_id` |
| `all_orders` | Заказы клиентов | `order_id` |
| `order_items` | Товарные позиции в заказах | `order_id` + `product_id` |
| `order_status` | Справочник статусов заказов | `status_id` |
| `order_status_history` | История изменения статусов заказов | `history_id` |

## 3. Основные связи между таблицами

- `customers` → `all_orders`: один клиент может иметь несколько заказов (One-to-Many).
- `all_orders` → `order_items`: один заказ может содержать несколько товарных позиций (One-to-Many).
- `products` → `order_items`: один товар может встречаться в разных заказах (One-to-Many).
- `all_orders` → `order_status_history`: у одного заказа может быть несколько записей истории статусов (One-to-Many).
- `order_status` → `order_status_history`: один статус может использоваться во многих записях истории (One-to-Many).

Таблица `order_items` хранит отдельные товарные позиции внутри заказов. Её первичный ключ составной: `order_id` + `product_id`.

## 4. Аналитические возможности

Структура исходной базы позволяет решать следующие аналитические задачи:

- Расчёт выручки на уровне товарных позиций и заказов.
- Анализ продаж по товарам.
- Анализ покупательского поведения клиентов.
- Анализ статусов и жизненного цикла заказов.
- Анализ истории изменения статусов заказов.

Выручка на уровне товарной позиции рассчитывается по формуле:

`quantity × unit_price`

Поле `unit_price` в таблице `order_items` позволяет рассчитывать выручку по цене, зафиксированной на момент оформления заказа, а не по текущей цене товара из каталога `products`.

## 5. Особенности и ограничения исходных данных

- Информация о статусах заказов представлена как в поле `status` таблицы `all_orders`, так и в отдельных таблицах `order_status` и `order_status_history`.
- При проектировании DWH необходимо проверить согласованность текущего статуса заказа и истории его изменений.
- Поля `status_begins` и `status_ends` в `order_status_history` позволяют анализировать периоды действия статусов.
- Исходная база является учебным проектом и не представляет собой промышленную операционную систему.

## 6. Статус реализации

**Реализовано:**
- Исходная база данных PostgreSQL `FOR CV`.
- Шесть таблиц.
- Первичные ключи и связи между таблицами согласно ER-диаграмме.

**Предлагается к реализации в рамках архитектурного проекта:**
- Слои аналитического хранилища данных.
- Трансформации данных с использованием dbt.
- Автоматизированные тесты качества данных.
- Инкрементальная загрузка и обновление данных.
- Аналитические витрины (Data Marts).

Таким образом, существующая база PostgreSQL выступает источником данных, а архитектура DWH и процессы dbt рассматриваются как проектируемое расширение системы.
